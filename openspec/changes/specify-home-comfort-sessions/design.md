## State, effect and concurrency contract

Home owns a `comfort_sessions` domain record: session UUID, room/sensor/optional actuator refs, owner origin, exact contract/profile digest, immutable start/expiry/achievement deadline, generation/revision, command effect ref, state, attainment summary and terminal reason. One unique active room and one exclusive active actuator claim are enforced atomically. Source facts stay with their existing owners; this record is not a new shared perception store. Proposed observation states are `requested`, `observing`, `holding`, `not_achieved`, `unmeasurable`, `relinquished`, `stopped`, `expired`; separate command status is `not_requested`, `awaiting_approval`, `denied`, `approval_expired`, `precondition_failed`, `failed`, `unverified` or `verified` and references the authoritative approval/HA receipt. Historical `first_attained_at` and `deadline_missed_at` never change current-state truth.

Start validates exact mapping, source, band, units, duration, profile and active claims in one transaction. Observe-only enters observing. Set-and-observe also begins observation while obtaining its single action permit through existing risk policy; an owner request is not a substitute for a required per-event approval. No approval need is removed. Only the exact unchanged action can reach dispatch. The existing effect execution fence rechecks session generation/expiry, current control claim, current room and HA source freshness, current actuator units/mapping and exact expected pre-command state; failed or unknown preconditions refuse without a physical send. Approval never refreshes evidence. Session Stop and that fence must share the existing authority contract: a separate best-effort precheck is insufficient. Home does not invent a second approval table or provider-send path.

Rejected/expired approval, failed execution preconditions or definitive failed send permanently remove that session's remaining action opportunity and continue observation with the specific command status only when no terminal fence has fired. Stop, expiry and confirmed external override take precedence and remain terminal; they cannot become active observers through a failed-precondition handler. Release the actuator claim only when no unknown or in-flight effect remains, retaining the room's observation session when still nonterminal. Such a downgraded observer does not fight or interpret later external actuator changes as its own actions. No automatic retry follows source recovery; further control requires Stop and a new owner-authorized session. An unverified effect likewise permits only observation of a nonterminal session and preserves an actuator reconciliation hold, not another send.

Attainment enters holding; any outside-band observation changes current state to observing immediately, with separately bounded drift notification hysteresis. After the first deadline miss, current state remains not_achieved until fresh dwell proves late attainment or expiry. Unmeasurable clears only after new valid source reconciliation, and a full new dwell is required. Deadline evidence is append-only. Relinquished/stopped/expired are terminal. Stop and expiry release control claims only when no unresolved effect can still dispatch; unknown effects retain a reconciliation hold on that actuator even if session metadata is terminal. A fresh Start against a held actuator refuses with the required reconciliation action.

For sessions still holding a control claim, external setpoint/mode/unit/mapping changes relinquish immediately; compare the original command's provider correlation and exact expected before/after values, not just whether the new setpoint equals the target. If correlation cannot distinguish an external command, fail conservatively to relinquished/unmeasurable and do not send. Never automatically reacquire. Same action identity and digest returns its prior result; a changed digest refuses; stale revisions return current state without effects. Changing the target creates a new owner-approved session after explicit Stop, not a mutable grant.

On expiry retain attained-ever and last measurable state separately; `expired` alone is never success. The terminal transition may create only one canonical terminal-report intent keyed by session/generation/terminal outcome, under the current authenticated owner route and ordinary attention policy; it cannot restart monitoring or physical work. Stop returns its solicited action receipt and suppresses any new proactive terminal report. Default expiry leaves the actual thermostat setting unchanged and says so before Start; automatic restoration is outside v1. A later owner-requested restore is a separate exact action, requiring current control/source and expected-state validation under RFC0028. Stop cannot undo heat already transferred.

## Interfaces and UX walkthrough

Proposed Home capabilities: `comfort_session_start` (exact room/sensor/band/mode/actuator/setpoint/expiry/profile and idempotency key), `comfort_session_read` (ID), `comfort_session_list` (max50), `comfort_session_stop` (ID/current revision/idempotency key). The broker/dashboard derives owner identity and grants; body fields cannot assert authority. Owner callbacks use canonical RFC0038 S6 authenticated subject/action/argument/generation tokens. No arbitrary HA service payload or expression is exposed by this API.

Entry is Home -> Rooms -> target room -> Comfort session. Known validated mapping pre-fills source fields; band and control mode remain explicit. First glance shows current reading with age, desired band and end time. Before Start, `set-and-observe` explains its one exact setting and that expiry will not restore the previous setting. Show command receipt and measured outcome on separate lines. Pending feedback within100ms; current evidence remains visible; Stop stays available. Repeat clicks share the idempotency key. Errors identify source recovery, conflicting session, required approval or actuator reconciliation. Keyboard order follows reading order; focus remains visible and status uses text, not only color. Dispatch tokens/controls apply. Repeated use can retain a proposed band but never preselect authorization or hide mode/expiry.

## Failure reporting boundary

Five-second miss detection assumes a live recorder or caller. If persistence/control-plane service is unavailable, the live API/UI caller surfaces timeout or unavailable within five seconds and never confirms the operation; durable reconciliation later preserves the original deadline and failure timestamps. A complete process/host outage is outside the supported latency conditions and is reported as an outage on recovery, never as timely success or proof of a durable write during downtime.
