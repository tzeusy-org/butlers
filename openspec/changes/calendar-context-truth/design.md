## S2: General's source query and deterministic transition

The existing context_producer_calendar registry entry and General */10 cron remain the only producer topology. Its pool/search_path reads General's own calendar_events projection; no sibling calendar query or live provider call. Expand the successful query to include event ID/source ID, event_type/working_location and all confirmed rows whose starts_at <= DB now < ends_at. The old all_day=false restriction moves into the ordinary branch so typed day-only working location is reachable. Do not apply an SQL LIMIT before eligibility filtering. Use one captured database instant per read/selection and compare aware boundaries end-exclusive.

Selection/eligibility matrix:

| Input | Required interpretation |
|---|---|
| confirmed default-family timed, attended opaque | meeting, or old title-marker focused fallback |
| self declined (either response key) | excluded from ordinary meeting/focus and OOO attendance; compatible other live candidate can win |
| transparent ordinary/focus/OOO | excluded from busy context; no phantom meeting/focus/away |
| guest declined; owner tentative/needsAction; missing/malformed metadata | keep existing attendance compatibility; do not invent exclusion |
| default-family all_day or legacy >=24h valid-zone local-midnight row | no ordinary meeting/focus; preserve old negative and timed human positive |
| explicit butler_generated true | retain projection; exclude every derived calendar branch; no title/source inference |
| valid confirmed timed outOfOffice, including multi-day/midnight | away('out of office'); highest attendance priority; never meeting or focused |
| typed all-day OOO/focus (unsupported provider shape) | preserve row; do not fabricate typed context or fall back to meeting |
| valid confirmed timed focusTime | focused regardless of title, subject to attendance/provenance; default title fallback remains |
| workingLocation valid shape, current window and valid IANA timezone | separate working_location; transparent is allowed; self-decline/generated excludes; never meeting/focused merely from this row |
| workingLocation bad discriminant/label/timezone or one-day-date boundary invalid | no location assertion; no title/address/identifier guess |
| future unknown bounded type | preserve raw type and ordinary default-family behavior; it counts when otherwise eligible |
| cancelled/tentative event status or ended/not-started event | no producer assertion; confirmed attendee tentative is a distinct accepted compatibility case |

OOO outranks all ordinary/focus candidates regardless of latest-start order. Otherwise select latest starts_at, then stable event UUID tie-break among ordinary/focus candidates, preserving the old latest-start preference. Location is independent: prefer timed over all-day, then latest start, shortest duration and stable UUID. Do not invent provider creation/recurrence precedence because current projection does not retain recurrence-instance provenance sufficient for the full Google UI ranking. This is a documented deterministic local selection rule, not a claim of perfect Google UI equivalence. Location may coexist with meeting/focused or away; it does not claim physical presence or suppress notifications.

Transitions are ordinary General non-DND writes. One acquisition/transaction covers selection and its set/clear changes; serialize concurrent executions of this ONE producer with a transaction-scoped advisory lock keyed solely to calendar-context/general, not a global auth/subject/phone lock. Acquire this scoped lock before observing source state, then apply managed signals in stable order. Re-query after lock acquisition; retry the whole transaction on a real retryable database concurrency error, not individual statements. Atomic rollback leaves previous state unchanged; report failure rather than catch-and-continue in an aborted transaction. No request/custody COMMIT authorization rule, signer, session mint, listener, new privilege or DND guard is introduced. The ordinary helpers accept the transaction connection for execute operations.

On OOO: set away with fixed qualified value 'out of office', metadata source='calendar', selected event/source IDs and event_type; clear General meeting/focused. On ordinary/focus: set selected meeting/focused with existing title behavior/default qualifier or fixed 'focus time' for structural focus; clear its sibling; retract only calendar-marked General away. Independently set valid working_location or retract only calendar-marked General location. On successful absence: preserve old clearing of General meeting/focused; retract away/location only WHERE writer=general AND metadata.source='calendar'. The source marker in this conditional cleanup distinguishes calendar rows in an already-authorized General slot; it is not an authentication boundary. Preserve other writers and an explicit non-calendar General away/location. General's existing unique writer/type upsert may replace an older General assertion while this producer asserts a real current declaration; no second source row, history store or new override precedence is introduced. On query failure, no absence transition runs: retain old bounded state to its TTL and expose the existing job failure, not fabricated currentness.

Expiry: use event end and existing set_context caps (meeting 4h, focus 8h, away 30d). Reassert on each successful run so an eligible long OOO never becomes indefinite and can remain active beyond the first cap. Working location requests min(event end, next local day boundary) and its 24h maximum/default12h; handle DST as aware timezone day boundaries, not now+24h as a local-midnight substitute. A fall-back 25h day may be clamped earlier until the next successful reassertion. All state is projected/scheduled declaration, not sensor proof of attendance. Existing calendar sync freshness/deadman/failed scan contracts remain separate; source read success does not certify provider or fleet freshness. Logs/counters carry only operation/result/fixed semantic classification/count/timing, never the raw unknown event_type. No title, label, attendee, calendar/source identity, provider URL or raw errors are logged.

## Engineering decisions and limits

E1 preserve existing RSVP compatibility rather than exclude tentative/unknown: exact governing authority and smaller blast radius; reversible.
E2 omit eventTypes rather than finite allow-list: official all-types contract and mandatory unknown fallback; reversible.
E3 new projection columns plus non-destructive retained-column downgrade rather than title guess/backfill/deletion: original S1 and data preservation; reversible source/schema compatibility, no destructive action enacted.
E4 typed OOO bypasses ONLY legacy ordinary-midnight inference; supported Google OOO/focus timed shape retained ([Google status-event guide](https://developers.google.com/workspace/calendar/api/guides/calendar-status)), all-day typed diagnostics produce no invented signal.
E5 location is declaration, separate from physical presence; typed labels minimized and current-day bounded; no auth/privilege shift.
E6 preserve broker suppression set, and fix actual prep selectors/starting-soon source instead of assigning nonexistent provider work to the broker.
E7 day-hours-only flag rather than remove OOO from shared candidates: literal no-conflict-policy-change contract preserved.
E8 one scoped producer transaction/serialization and metadata-conditioned cleanup, not a global admission/current-at-COMMIT rule.
E9 serialize complete existing active Write Permissions block with one additive row; do not duplicate, archive or tick foreign native work.

No hard-gated delta beyond the released original feature was found. Missing implementation seams, field normalization, TTL, tie-breaking and tests are engineering choices, not a request for another owner release. The original no-start owner dependency is historical/closed and no new ancestor dependency is added. Specific readonly-source risks remain visible: recorded typed-response fixtures not yet established; projection may be stale despite a successful SQL read; foreign/unpublished writers are unknown; migration revision is unallocated; SQL/rollback/roles/privacy/restart guarantees are plans until their genuine controls pass.
