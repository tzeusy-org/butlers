## Goals / Non-Goals

Restore a trustworthy detect → admit → investigate → propose → review → deploy → verify loop with bounded reasoning and honest evidence. Reduce recurring operator diagnosis and repeated LLM work. Preserve deterministic discovery, ephemeral reasoning, QA ownership, core-only runtime management, read-view restrictions, empty investigator MCP maps, restricted publication and human merge authority (vision Rules 2–7; development doctrine; RFC0015).

No generalist runtime rollout, higher concurrency/frequency, new connector, model pricing system, automatic merge/deployment, generalized durable message bus, second dashboard inbox or new dashboard page. Backward compatibility is waived: stale artifacts, false repair KPIs and dead routes should be removed. That waiver does not waive provenance, privacy, retained history, finite work or database authorization.

## Decisions

### 1. One accountable runtime capability

Core owns a QA-bound launch capability, registered by the QA daemon and fenced by lifecycle generation. Module QA may request work but never mutate spawner/session internals. Replace process-global last-registered-spawner selection, not the whole runtime API. The capability carries QA prompt/configuration, session-store identity and accounting owner. Finding `source_butler` remains diagnostic context. Resolve model eligibility once and pass that pinned resolution to launch; if invalidated, repeat admission. No fallback to a reporting butler. Initial and follow-up paths use the same capability. A stale generation refuses; old shutdown cannot remove its successor.

The core launch seam allocates session identity and persists attempt/session/phase lineage before agent execution. A reservation with uncertain launch outcome is reconciled using this receipt, never interpreted as no execution. Persist actual start/end timestamps; bookkeeping after awaiting completion is not phase duration. Preserve empty MCP, QA-specific prompt opt-out and credential-free workspace boundaries. Generic spawner termination semantics remain owned by `bu-2jtfw.5`.

### 2. Fresh evidence and separate outcome axes

Trusted dispatch creates an invocation-fresh output directory inside the isolated disposable checkout, outside tracked paths and excluded from every Git export and nonce for each invocation. The dispatcher creates the output directory with write access only for the investigator sandbox and read access for the trusted collector, no publisher state or credentials, and removes it after receipt persistence/retention-safe teardown. The collector seals/quiesces the writer before reading. Schema-v2 notes must match invocation/session, attempt, source evidence revision and pinned base/proposal head. These identifiers are trusted dispatcher expectations, not accepted merely because the agent echoed them. Open without following symlinks, bound bytes, consume the same validated descriptor, and enforce containment; mtime is not provenance. Retire tracked `.qa/investigation_notes.json` and update all producing prompts/skills. Store raw logs only in the existing private evidence field under its retention policy; sanitized descriptions and GitHub payloads obey the publisher contract.

`diagnosis_outcome` is one of `inconclusive`, `blocked_environment`, `operational`, `already_fixed`, `design_required`, `patch_ready`. Execution lifecycle, publication state and recovery evidence are independent axes. Empty/no-op process success is inconclusive, with attempt lifecycle status failed and the actual completed session execution outcome retained; it never becomes unfixable or resets a failure streak as resolution. `unfixable` is retained only for evidenced operational diagnoses. Already-fixed needs exact relevant revision and a passing reproducer. Patch-ready needs immutable base/head and a verification receipt. Design-required needs the governing requirement and proposed delta; retain it for owner review without publishing unauthorized behavior. No-model prelaunch refusal remains a dispatch decision, not a failed execution. Preserve anonymization_failed for publisher validation refusal. B owns one canonical session-completion breaker-event producer/projection and every current API/admission/reset consumer; C only integrates its new admission caller. Initial and follow-up session identity plus authoritative ended_at orders contribution; PR closure is not an execution event, and late pre-reset completion cannot resurrect the old streak.

Preserve original historical rows. Derive idempotent `legacy_unverified` or `contaminated` annotations from missing provenance or proven inherited content; do not rewrite old diagnoses, fabricate new ones or replay work. The UI falls back to source findings. Diff preview spans pinned base..head, not HEAD~1; truncation never grants publication authority.

### 3. Durable admission, incident identity and finite work

Store QA-owned incident generations, source-observation links, evidence revisions, pending dispositions, fenced leases and work reservations in migration-managed records. Link existing findings/attempts; keep source fingerprint semantics and original source evidence. Trusted shared occurrence/session/request/condition lineage permits correlation. Similar text, same call-site or a model-inferred root cause alone does not. Where linkage is absent, keep distinct incidents. Completed recovery followed by a fresh failure creates a regression generation.

A pending finding survives capacity limits and crashes beyond the discovery lookback. Claim with a lease and increasing fence; acknowledge only atomically with linked attempt or explicit final suppression disposition. Stale claimants cannot acknowledge successors. Fail closed if persistence is unavailable. Keep ordinary triage filters and active-condition suppression before authoritative atomic claim. `dispatch_pending` is not introduced as a healing-attempt status. Use a separate pending-work record as sole queue authority; retire dispatch_queued and get_dispatch_queued_findings instead of maintaining two mutable queues.

Cooldown expiry, dismissal expiry, polling time, count-only changes and paraphrases do not reopen an unchanged outcome. A changed relevant observation, configuration, deployment or severity can create a material revision; all ordinary gates and publication ambiguity holds still apply. Defaults: three launched sessions and sixty cumulative active minutes per incident generation, initial and follow-up combined. Reserve atomically before launch, reconcile crash receipts, charge actual active time, stop at the smaller existing phase limit or remaining total. Human-review wait consumes no runtime. No cooldown/restart/feedback reset. Exhaustion requests operator disposition; this plan adds no retry endpoint or budget-reset API.

State tables must deny writes from unrelated runtime roles, including after bootstrap grants replay. Use migration-managed role/RLS enforcement and real `SET ROLE` verification. Reuse `bu-w24vr3` for broader existing patrol evidence authority; do not claim this epic alone fixes all public grants. Durable dashboard inbox delivery remains owned by its active changeset: connect canonical finding acknowledgement to backlog persistence, not a second inbox. Ordinary butler relay buffering remains explicitly volatile until persisted.

### 4. Source-neutral bounded discovery

Each source returns findings, generation-bound continuation, covered boundary and complete/partial/unavailable status. Commit progress only with persisted findings or explicit durable exclusions. Use overlap for late arrivals and stable source occurrence keys for idempotent replay. Catch up beyond ordinary lookback using bounded batches; cap bytes before materializing/parsing, lines, candidates, findings and wall time. Persist fair continuation across sources. Cap exhaustion means partial; no source read or retention loss may advance a clean boundary.

Rotation/generation changes require validated continuation or an explicit irrecoverable coverage gap. Unavailable intervals never count as clean. Separate scheduler liveness, source availability and discovery completeness; complete suppressed patrols still qualify as discovery coverage, synthetic/legacy or partial patrols do not. Reuse run18 `bu-dss7he.13` as the log-backend owner; no competing scanner replacement. If its successor removes file scanning, transfer these requirements to the surviving sanctioned source before implementing, under this same owner gate. A blocked predecessor is an honest dependency, not grounds to silently waive log-only coverage.

### 5. Governed proposals and feedback

Investigator prompts load applicable doctrine, RFC and capability requirements, then reproduce, correct and verify using the exact-node/file/planner ladder. Shared generic agent duties remain opted out: no Beads management, remote credentials, review approval or merge authority inside investigators. Contract/permission changes produce design-required proposals. A bounded current-spec correction can proceed autonomously.

`bu-mc01y5.3/.4/.2` remains sole owner of RFC0015 restricted publisher implementation, verifier and source reconciliation. This work produces/consumes its immutable proposal and publication receipts. Unknown remote effects retain the lineage hold even after new evidence arrives. Repository capability outage records one action-needed condition from those receipts and reuses retained patches, not repeated code-generation runs. No new credential probes or permission scope.

Poll PR/head/checks/unresolved inline threads through complete supported provider projections, including pagination. Missing pages or failed reads are unknown. Persist a feedback digest and fenced follow-up claim bound to PR and expected head; concurrent timer/patrol polls cannot duplicate a launch. Revalidate head/policy/budget before launch and publisher preconditions before mutation. Same consumed feedback does nothing. Follow-up shares the incident work budget; draft/read-only identity proofs are not operational publication proof. Sanitized response drafts remain local for operator handoff. QA does not post or resolve review comments. Only bound branch updates and permitted PR title/body/fixed-label updates use the existing publisher; review-comment mutation needs a separate approved authority change.

### 6. Verify recovery and show the real funnel

Retain existing QA routes and Dispatch components. Preserve force-patrol/reset/dismiss behavior, session evidence doors, degraded-query behavior, keyboard interaction and accessible text. Consume `bu-dss7he.1` dead Retry removal; do not restore the old endpoint. Add distinct outcome/provenance/publication/deployment/recovery facts to case projections. A merged PR is merged, not repaired. Null PR URL alone cannot prove unpublished. Inconclusive copy is not crash copy.

Recovery needs trusted deployment evidence matching the proposed fix revision and either (a) a safe reproducible regression check against that deployment, or (b) complete relevant source coverage with at least one qualifying recurrence opportunity of the failed operation and no matching failure. An empty idle patrol is not a recurrence opportunity. The observation receipt records start/end, source generation, exact workload/check and result. No universal clean-patrol timeout is proof: if the opportunity cannot be observed, recovery stays unverified indefinitely and its age remains visible. New matching failure produces a linked regression. This work may observe deployments; it has no deployment authority.

Summary wire shape adds `funnel` stages `{observations, admitted_incidents, proposals, published_prs, merged_prs, deployed_incidents, verified_recoveries}`, each with unit, count-or-unknown, window and coverage; `recovery_rate` has explicit numerator/denominator; `usage` has session coverage, active duration and separate input/output/cache counters by reported model with billing unknown where absent. Windows are event-time cohorts with timestamps named; the ratio uses recovered generations / eligible deployed generations within the same cohort, not attempts or PR counts. Existing unrelated health/configuration fields survive. Remove merge-derived MTTR/self-resolved fields and their consumers together. The exact stage timestamps, failed-execution membership, active_cases/active_breakdown and current/prior cohorts are defined in the summary spec; failed attempt status alone is not a failed execution. Existing five-cell strip becomes PRs landed, verified recoveries, recovery-verified percentage, active cases, failed executions; details expose the full funnel without adding page chrome.

Requested/served model and billing provenance consume `bu-s11n0s.6` receipts. Do not manufacture cost from model names. Historical missing linkage stays unknown. A cheap patrol remains the safety net; deterministic state changes and durable backlog decide whether any reasoning is warranted. Tune cadence/model policy only after this evidence exists.

## Migration and rollback

One serial lane, six outcomes then one end-to-end closeout. Each outcome owns its migrations, producers, consumers and focused proof. Within each outcome: represent optional evidence first, propagate all current paths, then enforce only after coverage is proven. Compatibility waiver permits atomic API/consumer removal; never run a new strict reader against an old writer during rolling deployment. Deployment must quiesce QA reasoning, finish/reconcile active leases/publication holds, apply migrations, deploy matching producer/consumer versions and smoke-test before resuming. Deterministic observation may continue only where the representation permits it.

Rollback holds QA reasoning, retains new evidence/pending work, disables new launch paths and restores a matching reader/writer release; no downgrade that drops evidence or restarts ambiguous publication. Old note files and forged health metrics are not rollback destinations. Database migration proof includes core-only application, repeat bootstrap under real roles, duplicate/replay, partial failure and read-back from separate connections. No active state is pruned as cleanup.

## Risks / Trade-offs

Strong evidence can reduce apparent success rates; that is desired truth, not a regression in service. External blocked owners delay runnable work; keep dependencies rather than competing implementations. Incident correlation intentionally under-merges when provenance is missing. Recovery can remain unknown for rare operations. The three-session/sixty-minute default bounds cost but may stop a valid repair; exact adoption can change it before release, not silently at runtime. More schema state needs migration and authorization proof; reuse current QA stores and publisher lineage instead of inventing a general workflow engine.
