## Intent and authority

The owner needs to distinguish the model selected for an invocation from the model identities actually reported by its runtime, and distinguish a successful process exit from a successful model result. The governing authority is the existing run-16 release bu-9zmre6, the complete original bu-s11n0s.6 fields, the model-catalog Durable Model Resolution Receipt and Adapter Token Reporting Contract, core-spawner Runtime Failure Classification and Logical Session Attempt Orchestration, dashboard-spend-dashboard Spend API, dashboard-visibility Session Detail Drawer/Full Page, build-reproducibility LLM CLI runtime toolchain, and the existing model-failover side-effect gates. The quoted original fields and exact clause map accompany this protocol.

This adds evidence within existing adapters and existing dossier/spend surfaces. It does not introduce another provider, model-selection policy, paid service, model probe, owner permission, credential, signer, principal, cross-butler call, or persistent global authentication mechanism. The word attestation means bounded adapter-origin evidence here, not cryptographic proof of a provider's internal deployment. Host/database/migration trust and untrusted ephemeral session boundaries remain exactly the current doctrine. Ordinary public-table grants do not prove that a malicious runtime cannot forge a row. No new security boundary is claimed.
