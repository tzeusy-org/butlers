## Storage and capture authority

Reuse `general.collection_items.data.possession_profile` and existing UUID. No new table or schema namespace. One minimal General migration adds `collections.custody_private BOOLEAN NOT NULL DEFAULT false` and replaces the existing global name unique constraint with `CREATE UNIQUE INDEX ... ON collections(name) WHERE custody_private = false`. Existing IDs, names and contents remain unchanged. The reserved column is server-owned, absent from generic request schemas and not mutable through model tools. Private enrollment sets it true transactionally; retirement, item moves and loss never reset it. No automatic declassification exists. Profile holds schema version, revision, append-only events/projection, private pending confirmation and immutable accepted receipts. The marker is code-reserved: generic writes cannot introduce or remove it. Enroll locks the item and establishes protection atomically; all newly stored report data is written only after that fence. Every protected item is wholly withheld from generic model reads, not merely redacted at one endpoint.

Private `/prepare` validates selected item, action, episode, expected revision, operation identity, reported fields and observed time. It stores a pending canonical report under the protected profile, issues an unguessable confirmation nonce bound to the server principal and item, and expires it after ten minutes. The UI displays exactly those normalized fields. `/confirm` accepts the nonce and operation identity under the same owner authentication, validates expiry and stored digest/expected revision, and commits event/receipt/projection together under row lock. The nonce never reaches models, URL, log or tracing. The event source reference is a local immutable private capture/confirmation receipt, not a fabricated conversation source. Unconfirmed pending drafts never enter history or affect projection; expired pending drafts are discarded on the next private access. Client drafts remain memory-only and disappear on navigation/logout. Confirmation retries check the existing operation first and return the original private receipt, even after later revisions. Changed operation payload refuses without mutation. Raw draft text and private validation messages are not generic audit payloads.

This replaces the original LLM proposal and Switchboard receipt seam. Ordinary ingress cannot create or confirm custody. If a user voluntarily typed a sensitive sentence in ordinary chat, existing processing may already have exposed it; the feature never claims retroactive confidentiality or a universal chat redactor.

## Episodes and concurrent writers

Preserve the original contract: move changes place, not episode custodian; borrow and lend have opposite owner perspectives; one active episode per item; return names exactly that episode; retirement requires no open episode and retains history. Correction appends, preserves action/direction/event/episode identity and validates dependent events before projection recomputation. Observation time differs from server record time; late reports do not replace newer truth silently. Equal-revision writers have one winner; operation replay returns its original event. Model-facing and generic API mutations of private items or their parent collection always return the same fixed unavailable-target refusal, including unrelated JSON/tag writes. They cannot produce a successful mutation or record-specific conflict as an existence oracle. Trusted deterministic private-owner unrelated-field updates alone merge under the same lock or conflict privately; they never overwrite newer history. Item/collection deletion must atomically refuse protected items, including enrollment races. No implicit opt-out; explicit destructive deletion requires a future adopted contract.

## Ordinary name namespace and durable migration

The current General collection_create uses a globally unique name and item_create first looks up that name then auto-creates/upserts it. Merely hiding reads would still leak private existence via conflict or insert behavior. The successor explicitly splits name resolution, not storage ownership: ordinary name uniqueness uses the partial index above; private names are not globally unique, and private UI always selects UUIDs. Generic collection_create preserves its ordinary duplicate-name semantics only for ordinary rows. Generic item_create SELECT uses custody_private=false and its ON CONFLICT target uses the same partial-index predicate. A private-only matching name is absent in this namespace and creates a new ordinary row; no synthetic hidden-name conflict is returned. Generic export-by-name and all alias/name resolvers also filter to ordinary before resolving. The same text can therefore name a private and an ordinary collection, displayed distinctly in private owner selection. Enrollment disclosure explains this namespace effect along with sibling hiding.

A generic create acquires the resolved parent shared lock and rechecks custody_private inside the insertion transaction; enrollment uses the parent exclusive lock. If enrollment wins first, create retries ordinary-only resolution/creation without returning protected status; if create commits first, that item becomes part of the subsequently enrolled parent. Partial uniqueness arbitrates concurrent ordinary creates. Collection-name updates/membership moves use the same lock order and ordinary-only namespace contract. Integration with bu-2jtfw.9 must map its vocabulary/aliases to this exact boundary before dispatch; no alias may return a private UUID.

Migration tests must apply the actual General chain, preserve preexisting ordinary rows, prove partial uniqueness and private-label coexistence, and test downgrade refusal. The database migration does not itself enable enrollment; marker-aware routes/fences must be installed before any true marker. Private rows and duplicated names make a blind old-binary/schema rollback unsafe; preserve the new privacy layer until separately adopted declassification work exists. No claim is made to hide names already learned by an owner/model, remove old messages, or equalize physical timing; the contract forbids feature-generated private-name conflict, row reuse, counts and record-specific success/failure disclosure.
