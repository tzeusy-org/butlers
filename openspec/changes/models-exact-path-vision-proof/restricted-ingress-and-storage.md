Existing backup architecture must review exact role/restore integration; no backup runtime changes are executed here. Restore imports through a fixed validated import procedure under the same role, not disabling forced RLS or TRUNCATE fences.

Never expire an applied proof or consumed operation replay tombstone merely because its signing token expired. V1 retains terminal content-blind receipts/application history/replay identities indefinitely; no age-based purge is introduced. Synthetic image objects alone expire after comparison or interruption cleanup, with cleanup receipt. Restored terminal spent slots stay consumed. Applied proofs tied to old environment epoch become stale until a new exact proof and explicit application; no automatic historical rewrite. Restoring an older backup must not accept unexpired capabilities created after that snapshot: mandatory epoch rotation before startup, not reliance on receipts absent from backup. Disposable full backup/restore tests must prove schema+data recovery, forged replay rejection, no duplicate launch and new-epoch activation separation.

## Restore epoch implementation contract and owning paths

The control service MUST refuse every read-to-execute transition and issued capability until restore status and fresh epoch are installed, all restored running slots marked interrupted, and old-epoch authorities invalidated. Every issued vision capability includes this epoch in its signed exact payload; every private receiver checks equality to the active host epoch BEFORE nonce claim, attachment access or provider effects. Startup/restore failures fail closed; ordinary text probe tokens do not gain this field or authority implicitly. No current implementation is claimed.
