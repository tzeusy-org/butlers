## Proposed amendment 1

The Model functions bullet in [RFC 0038 D18](../../../about/legends-and-lore/rfcs/0038-goal-runtime-and-capability-authorization.md#d18-model-use-outside-goals) and its RFC 0036 disposition row assign vision proof to deterministic model functions. PR #4360 covered the older CLI/MCP diagnostic configuration. A tuple unable to enforce D18 and the operation envelope ends Not run.

Each control makes one tool-less, single-turn, structured-output call through the exact row's runtime adapter. Only the positive control has an inline image. The text-only control has no image part and the removed-image control removes that part after creation and before request assembly. All three calls share the exact runtime type, model ID, runtime/CLI version and account path. The adapter must establish the tool, turn, output and spend bounds before a call. The deterministic comparator reads only the typed answer. Both negatives must return `NO_IMAGE`.

Purpose-bound admission, durable per-control slots and spend reservation, private comparison, content-blind receipts, the restore epoch, explicit Enable/Apply/Refresh and exact-row compare-and-swap remain in force. Proof calls go directly to their authorized row through the bounded adapter mode. The existing fit and authority rules still govern ordinary dispatch.

The model-catalog delta keeps the existing exact-path scenario heading, tuple, evidence threshold and ordinary eligibility rules. It changes the probed image transport to the inline model-function path. The two named cases in `tests/core/test_attachment_view.py` and the attachment tool tests pin the server's MCP wire shape. Runtime-side MCP forwarding stays explicitly unproven. The model proof establishes that the exact model read an inline image on the exact tuple.
