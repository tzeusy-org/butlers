# Storage and API draft mapping

No revision numbers reserved. New core migration must work on core-only databases, replay per schema safely, and preserve existing public.model_catalog and text-probe contracts. Use PostgreSQL row locks plus canonical digest of all relevant row fields/envelope for expected-revision CAS; do not pretend current model_catalog already has a dedicated monotonic revision. Existing updated_at is part of evidence but alone is insufficient full-envelope/path equality. Representation fields below are proposed names, subject only to semantics-preserving engineering naming review.

public.model_vision_operations: operation UUID primary key; catalog UUID, owner actor, environment fingerprint, procedure version, expected row snapshot digest, purpose/authorization digest, exact runtime/model/adapter/CLI/config/account-path fingerprints; caps/reservation, stage/status/terminal category; created/expiry/deadline times; cancellation flag; receipt digest; cleanup status. A unique in-flight catalog key serializes concurrent operations; idempotency identity binds principal/catalog/request digest, not arbitrary reuse across a changed request. Persist no raw capability token or credentials.

public.model_vision_control_receipts: operation+control ordinal unique, control enum positive/text_only/removed_image; allocated/started/terminal slot state and times; synthetic source/session/storage-ref digest and expected tool/result-manifest digest; usage/counters; bounded typed verdict. The manifest's raw synthetic refs are private executor inputs, never a new arbitrary attachment permission. Slot reserve commits before launch; ambiguous started remains consumed. Durable per-request admission accounting checks total envelope before each provider request, not just sessions. Missing CLI enforcement yields not_executable.

public.model_vision_applications: catalog UUID unique, receipt/operation reference, applied expected/live path digest, applied timestamp, server actor, applicability generation. Apply locks row+eligible receipt; verifies all controls, unconsumed or idempotently same application, exact path and snapshot; merges only vision=true plus application binding atomically. A historical row has no application record. Reads of a latest successful operation do not touch applications. Deletion cascade/retention must preserve audit receipts without reviving a row; keep tombstoned catalog identity in receipt, never rebind by alias.

State writes belong only to authenticated private control/server-owned catalog application procedures. Runtime role privileges and forced RLS/owner-bypass fences must follow core201/core212 precedents with real bootstrap replay; no blanket public runtime DML or client-selected SECURITY DEFINER table/name. Maintain schema-owner separation; exact current roles and migration ownership verified before code. Error categories fixed. Audit carries operation IDs/outcomes, never raw sentinel/image/provider output. No schema grant executed live by source delivery.

Public owner endpoints use existing ApiResponse convention and authenticated_principal. Proposed GET /{id}/vision returns declared capability, latest_check, applied_proof, executability with bounded reason and server-preflight envelope display; POST /{id}/vision/operations takes idempotency UUID, expected row digest and server-issued preflight ID; GET /{id}/vision/operations/{op} returns durable status; POST .../{op}/cancel; POST /{id}/vision/enable takes receipt UUID+expected row digest. Enable endpoint renders Enable/Apply/Refresh labels according to row/binding state, same CAS semantics. Unknown/mismatched owner or row returns existing auth404 conventions without existence leak. Invalid wire422, stale/conflicting row409, busy existingoperation reference, missing authority unavailable/not_run with no side effects. Cancellation is idempotent and cannot erase receipt. No endpoints accept actor, arbitrary prompt/image/url/tool/model override or caller-generated capability.

Models non-vision edits retain whole-envelope replacement and validation; preserve untouched fields. Every path that writes a new vision=true value, including new, cloned, unbound and imported rows, or preserves true while changing relevant identity (including historical true rows) must verify/invalidate binding atomically, including bulk/import/admin mutation paths found in source inventory; no protection only on new endpoint. Historical unbound values remain as they were until explicit Apply/Refresh. Clear/disable actions are explicit owner CAS, never automatic probe failure handling. Preview estimated caps is not proof enforcement or live spend authority.

Only an existing historical declaration with unchanged bound runtime/model/account/config identity is grandfathered. Absence of an application record is NOT authorization for a new true write. Generic create/PUT/bulk/import/clone true requests require applicable proof; legacy-true identity edit cannot preserve true silently. Unknown/false remain available explicit outcomes. Tests must cover new/unboundtrue, clonedaliastrue, legacytrue model/runtime/account change, unchangedlegacytrue unrelated edit, managed true update and all discovered migration/admin writers.
