State key chronicler/owntracks/retention remains the declared owner surface, but a generic state write is not authority: the typed policy record is canonical, and the reserved state route delegates to the same protected setter; generic state_set cannot bypass it. The informational state representation is versioned and round-trips that canonical policy. Default creation is trusted startup, not model input. Existing OWNTRACKS_RETENTION_DAYS audit-row behavior is preserved separately and documented as not a second raw policy authority.

Each accepted raw row has immutable retention_at and source_revision/content digest. retention_at is the producer-captured effective event time using the existing4-hour skew rule (implausible device time falls back to original server recorded_at); it is never refreshed on duplicate/replay. Legacy rows derive exactly that same deterministic existing ts/recorded_at rule and require genuine coverage before forgetting. DB transaction clock anchors cutoff=run_started_at-days; equality survives (strict older-than), UTC only, no browser date/time. An accepted late observation remains discoverable independent of its device timestamp. A new genuine arrival may create new evidence with its own original birth; the same expired logical source key never gets a new birth. TTL guarantees are conditional on committed projection, and UI names the actual blocking state rather than calling retained overdue raw data forgotten.

Policy changes lock the own policy row and increment version via CAS. Jobs freeze policy version/cutoff and batch identity in durable records. A shorter horizon schedules bounded immediate work plus the normal six-hour retry; no delete before projection. Widening affects unprepared retained evidence and future arrivals; it cannot undo a committed retention decision/precision reduction, restore deleted points or remint an expired source. Preparation is the owning policy decision COMMIT: its exact expired, fully covered set is irreversible, even if raw deletion acknowledgement is still pending. The setter must tell the owner that already prepared batches may finish under their frozen policy, while subsequent preparation uses the new version. Do not imply a fresh authorization from an old mutable policy mirror. Prepared/coarsened and raw-forgetting-pending states remain visible and are not a claim the raw row was deleted. A missing or malformed policy fails closed and degrades status, never an unbounded/default-success purge.

Genuine replay of retained legacy rows through the actual adapters is mandatory to earn coverage.

## P3. Safe owning commits and cross-process purge sequence

Do not use one Chronicler role to DELETE connector data, or pretend two owning commits are atomic. Two committed stages with immutable source receipts provide truthful recovery:

1. Chronicler scheduled Tier0 job reads the approved raw source and takes its own policy/projection locks. It selects bounded eligible exact row revisions with complete applicable coverage, coarsens every dependent own projection/carryover/cache, creates monotone tombstones and an immutable grant manifest (run_id,grant_id,policy_version,cutoff,rawUUID/content digest/source revision,covered output revision,expiry). These changes and prepared receipt commit together. Failure rolls back all preparation. The initial committed plan is not a ready raw-deletion grant. All required own-holder privacy transitions must subsequently be independently read back through their registered owning MCP interfaces; only the same frozen plan with complete real holder receipts becomes a ready immutable grant. Only after that own ready-grant COMMIT can the constructor-fixed connector worker obtain it over the actual registered owning MCP read surface. Tool/request IDs only locate the engine's own stored grant; caller IDs/cutoffs/arrays are not deletion authority.
2. The actual OwnTracksRetention connector loop, under its existing connector_writer identity and fixed source configuration, obtains/revalidates the grant over MCP OUTSIDE its raw transaction. It locks a global OwnTracks retention batch mutex then raw identities in stable order, checks the immutable raw revision/content/birth and strict cutoff itself, and writes minimal permanent logical-key tombstones plus its connector-owned retention batch receipt in the SAME raw DELETE transaction. Changes/missing revisions refuse or record already-forgotten only against an actual matching tombstone; missing rows alone are not successful forgetting. Replayed expired logical keys cannot reinsert raw. No SKIP LOCKED/hidden skips, unchecked DELETE status parsing, deletion of unknown rows, broad partition drop or arbitrary endpoint/provider selection. Writer lock waits/DB errors roll back; network I/O never occurs under those locks. A short transport/claim lease bounds batch liveness: native acquisition and the final raw mutation gate check the database wall clock (not transaction-frozen NOW), with bounded lock/statement deadlines. Expired work reaching that gate refuses and rolls back. Commit-ack delay after that accepted mutation is UNKNOWN until the same committed source receipt is read; no exact wall-clock-at-COMMIT or cross-pool revocation guarantee is asserted. The lease does not undo the earlier irreversible privacy decision. The immutable prepared decision, not a claim that another pool supplied current policy at raw COMMIT, authorizes only this frozen set. Revalidating/renewing a claim recovers the SAME committed decision and does not elect new rows, extend their age or overwrite a newer policy. A concurrent policy setter controls future unprepared decisions; it cannot undo this committed privacy transition. This deliberately avoids an impossible cross-pool current-policy-at-COMMIT claim.
3. Chronicler reconciles the actual committed connector receipt using its narrowly declared approved SELECT source. It compares grant/source hashes, identity, counts and committed dispositions, updates the SAME run/grant receipt, and emits count-only freshness AFTER its own reconciliation COMMIT. Caller ACK/body/status is not evidence. Failed/lost raw commit ACK resumes SAME batch ID by separately acquiring the source ledger; existing committed tombstone/receipt proves the result, otherwise UNKNOWN. It never remints a new deletion set because an ACK was lost. If raw commit happened and Chronicler final ACK is lost, reconciliation repeats idempotently. Prepared/coarsened/unknown states stay visible and never claim all copies forgotten.

Existing trusted connector code is the raw writer/deleter, not a kernel-authenticated adversarial actor. A private grant does not isolate compromised trusted host/admin code; its exact runtime role, finite clock, native producer provenance and registered owning transport must be proved. Existing connector startup/stop must actually retain/start/cancel this worker, with restart reconciliation before fresh deletion. Independent run/up and separately hosted connector/Chronicler MCP topology are required positives; cohosting must not be the sole proof.
