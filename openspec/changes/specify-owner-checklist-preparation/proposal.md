## Why

An owner can supply a list of documents or proofs for an administrative task,
yet today must repeatedly open each source and compare it with each clause.
General's collection and export promises support organizing that work, but a
freeform collection cannot say which exact list revision was checked, which
source version supported a clause, or whether an apparent gap is genuinely
missing rather than unreadable. The useful outcome is a reviewed preparation
index, not a declaration by Butlers that an application is eligible or filed.

This is a **proposed** contract for run-14 `bu-p5umi2.4`. The released planning
gate `bu-04i7om` did not adopt feature behavior. General capture/vocabulary,
ownership refusal, and generic item paths belong to foreign `bu-2jtfw.9`.
The proposed personal-item custody package in draft PR #4211 is a distinct
General memory task. Neither package is adopted by this proposal.

## What Changes If Adopted

- Let the owner supply and revise an exact checklist, select specific source
  doors, review proposed clause-to-evidence matches, and see each clause as
  `missing`, `needs_review`, `unavailable`, or `covered`. First intake needs no
  existing packet revision; an owner-confirmed exclusion stays separately
  visible rather than silently disappearing from a later complete export.
- Define an owner-confirmed immutable preparation receipt and exportable index
  pinned to the exact checklist revision, its active and excluded clauses,
  and accepted evidence versions. Its only completion claim is **complete
  against the active clauses of the owner-confirmed supplied-list revision,
  with explicit exclusions disclosed**.
- Require an authoritative immutable source version, current read authority,
  a server-held pre-read owner selection grant verified by the source owner,
  and a commit-valid version fence. A caller-asserted source ID, filename,
  mutable locator, row ID, or fetched timestamp alone never qualifies evidence
  or authorizes release of a minimal specialist fact.
- Keep Finance receipts and transactions in Finance, trip documents in Travel,
  and all cross-butler specialist reads through Switchboard MCP. General keeps
  only minimal source doors and owner-reviewed coverage decisions.
- Propose bounded General manifesto and routing text in
  `general-manifesto-and-routing-amendment.md`; no canonical file changes here.

## Deliberately Out of Scope

No official requirement discovery, legal or immigration advice, eligibility
judgment, compliance certification, form submission, third-party account
access, payment, provider call, credential, new connector, or automatic
document gathering. No duplicate Finance receipt ledger, Travel document
registry, capture/vocabulary rewrite, generic expiry engine, or replacement
deadline/commitment state machine. A PDF cover sheet and new dashboard page
are not prerequisites. This package changes no runtime code, migration,
manifesto, routing config, live/private data, deployment, or external system.

## Authority and Adoption

The owner must adopt the exact OpenSpec and General manifesto/routing amendment
after independent review and reconciliation with the settled `bu-2jtfw.9`
head and draft custody proposal. A future implementation must separately
allocate the General-local packet store, owner-confirmation seam, and any
specialist version/read-fence tools. No Finance or Travel source is considered
implementation-ready merely because it has an existing row or blob reference.
The spec and future implementation may be declined without altering current
General, Finance, Travel, or commitment behavior.
