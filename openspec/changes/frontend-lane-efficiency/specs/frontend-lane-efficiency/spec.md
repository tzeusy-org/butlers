## ADDED Requirements

### Requirement: Independent required static and test outcomes
The CI system SHALL run exactly one ordered static chain independently beside both full Vitest children and SHALL require every applicable outcome under the unchanged required frontend/check contexts.

ID: REQ-frontend-lane-efficiency-001
Source: bu-ly3lv5.9 complete original7/base3/folded5; P0-P9; Five-Minute Routine-Lane Target
Scope: v1-mandatory

#### Scenario: Both independent failure causes are reported
- **WHEN** a knip failure and test failure are seeded in the same applicable run
- **THEN** both actual causes are recorded and frontend/check refuse success

#### Scenario: A moved check retains its survivor
- **WHEN** lint, copy, coercion, knip, typechecked build, owner-time, Node or CSS enforcement moves
- **THEN** its full scope and planted violation remain mandatory once in the static/test survivor ledger

#### Scenario: Build reuse retains provenance
- **WHEN** the browser consumes the single static build
- **THEN** actual source/run/attempt/config/lock/content evidence is verified without rebuilding

#### Scenario: Missing contributor refuses success
- **WHEN** static, a shard, artifact or exact event evidence is missing or unknown
- **THEN** the applicable always-running required verdict is non-passing

### Requirement: Private lint caches preserve rule enforcement
ESLint content caching and concurrency SHALL preserve complete source/rule selection and SHALL fall back to full lint when cache compatibility is unavailable.

ID: REQ-frontend-lane-efficiency-002
Source: bu-ly3lv5.9 complete original7/base3/folded5; P0-P9; Five-Minute Routine-Lane Target
Scope: v1-mandatory

#### Scenario: One changed file still fails lint
- **WHEN** a cache-hit one-file change introduces an actual rule violation
- **THEN** lint fails and the cache cannot grant authority

#### Scenario: A local rule change invalidates cached success
- **WHEN** local rule/config/script/locked dependency identity changes
- **THEN** the prior entry is not reused across that identity

#### Scenario: Corrupt cache runs full lint
- **WHEN** a cache is absent corrupt or of unknown runtime/source identity
- **THEN** complete lint runs with explicit finite degradation under unchanged bounds

#### Scenario: Concurrent lint retains exact semantics
- **WHEN** parallel lint and serial reference process the same current source
- **THEN** diagnostics and verdicts agree or serial execution remains required without dropping rules

Environment classification and date dependency optimization SHALL preserve the complete fresh installed item/assertion population, isolated-fork behavior and actual DOM/effect/date semantics.

### Requirement: Quiet console output remains a real failure gate
Unexpected console errors, warnings and unhandled test errors SHALL fail the owning test, while expected negative-path messages SHALL use explicit bounded local justification and restoration.

ID: REQ-frontend-lane-efficiency-004
Source: bu-ly3lv5.9 complete original7/base3/folded5; P0-P9; Five-Minute Routine-Lane Target
Scope: v1-mandatory

#### Scenario: Unexpected asynchronous errors are fatal
- **WHEN** an unexpected console.error is injected during a test callback
- **THEN** the real test and required frontend gate fail

#### Scenario: Expected errors are local and finite
- **WHEN** a documented negative-path error is deliberately tested
- **THEN** its exact scoped allowance restores afterward and excess or unrelated errors fail

#### Scenario: SSR and mounted effects are preserved
- **WHEN** act or useLayoutEffect warning causes are repaired
- **THEN** SSR output snapshots and actual mounted effects/cleanup retain their old assertions

#### Scenario: Whole test output is genuinely quiet

- **THEN** its stdout plus stderr is below1000000 bytes without hiding failures or truncating output

### Requirement: Browser and main event reuse remain fail closed
Browser concurrency SHALL use actual finite runner capacity and SHALL refuse flaky outcomes; post-queue main push SHALL retain fresh inventory while avoiding duplicate protected frontend and heavy checks. The route job MAY use only the existing repository GITHUB_TOKEN principal with actions:read for bounded same-repository protected evidence verification; this explicit read permission conveys no write or caller-verdict authority. Protected main reuse SHALL satisfy the complete event-applicability and independent lineage/fresh-survivor admission of REQ-ci-shard-assurance-007; a main label alone grants no skip authority.
