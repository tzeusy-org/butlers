## Data flow and trust
Daemon configuration -> registry.load_all discovery -> _select_startup_modules explicit declaration filter -> validation/migrations/startup -> register_tools(canonical butler_name) -> existing approval/catalog/state wrappers -> runtime wiring. Healthy, configured startup hook invocation membership equals declarations; failed, cascade-failed and user-disabled state remains separately visible and retains current behavior. Registry instantiation is not successful startup. An omitted schema-less module must have no startup/migration/tool hook. Before filtering the loaded list, _select_startup_modules SHALL compare all configured module names against the actual loaded registry names and raise ValueError for any unknown name, before provisioning, migration, startup or registration. Current load_all does not perform this check; preserving only the old load_from_config unit test does not satisfy actual startup's existing Unknown Module Names Block Startup requirement. Retain that API test separately, preserve deterministic dependency ordering, and keep runtime enable/disable from admitting an omitted module.

Registered report_error -> shared fingerprint/severity computation -> bounded Switchboard registry lookup -> actual Switchboard route MCP tool -> QA report_finding -> ButlerReportsSource -> later QA patrol/triage/dispatch. The reporting module performs no local active-attempt admission, investigation dispatch, redispatch, recovery, reaping or publication. QA's current recovery/reaper/global spawner hooks stay intact. MCP client transport is the only inter-butler path; no private API, direct QA pool/schema access, new role/schema/grant or extra target server is introduced. The emitter identity comes exclusively from register_tools; report arguments cannot choose source_butler, target, tool or dispatch config.

Normalize both actual FastMCP results (error flag, structured/data or text JSON) and the route envelope before acceptance. A route result {result:{accepted:false}} and a tool error/malformed/empty result are failures. Closed response reasons are disabled for disabled relay admission, qa_unavailable for no client/registration/registry read, relay_failed for rejected/error/malformed target results, and relay_timeout for deadline expiry; each includes accepted=false and the reporter fingerprint with a fixed content-blind message. Success remains accepted=true/fingerprint/message without attempt_id. The returned reporter fingerprint is a hint; QA independently canonicalizes the transmitted event summary/call site and may produce a different fingerprint for a truncated message or omitted caller call site. Do not change the hash algorithm or claim reporter hint equality for every input; SQL assertions independently recompute the actual QA input fingerprint. The direct target acceptance representation used by existing in-process test clients is compatibility input, not proof of real transport. Keep allow_stale=true, existing 60-second registry-cache behavior, optional context omission, current 200-character event-summary limit and sensitive error_message/traceback/context metadata. One overall two-second budget bounds cache miss plus route; expiration produces an explicit unavailable result. CancelledError remains cancellation, not success or a new fallback. Timeout or uncertain transport leaves QA reception unconfirmed: QA may already have buffered the finding, so accepted=false means no confirmed reception and no local dispatch, not proven absence of a central finding or investigation. Do not retry ambiguous tool transport, persist a new relay queue or claim durable acceptance. Existing QA buffer volatility, capacity warning, canonicalization and meta/self-recursion rules remain central.

## Concrete engineering choices and alternatives
[decision] Explicit startup admission: keep load_all instantiation of every registered module, but admit only names present in config.modules, including schema-less modules. Reason: the Round-2 exact declared started-set obligation and opt-in module doctrine; schema shape is not consent. Alternative rejected: documenting the current schema-less exception would weaken the accepted declaration contract. Do not delete Metrics/DocumentRenderer packages, queries or foreign requirements as part of this filter.

[decision] Unknown declaration admission: the owned _select_startup_modules seam rejects config.modules names absent from its actual load_all result before any downstream startup effects. Keep load_all discovery and load_from_config behavior unchanged. Reason: the existing core-modules Unknown Module Names Block Startup requirement and this packet's retained unknown-name failure obligation require actual startup rejection; today's registry-only test is positioned at a different API. Alternative rejected: silently filtering unknown names can boot a butler without the requested relay or provider. Extend C1 at real daemon.start/run_startup with an unknown-name negative plus a valid declared-module positive; spy on provisioning, migrations, startup and registration so rejection occurs before those effects. Do not mock load_all, the selector or run_startup in that proof. This is ordinary enforcement of adopted behavior within the same owned function, not a new authority or owner gate.

[decision] All-roster relay coverage: add empty [modules.self_healing] sections and ../../../shared/skills/self-healing links to all 13 current rosters, not only the nine domains. Report_error is required on every butler; QA self-reports keep existing source_butler=qa unknown/healing/qa-trigger meta suppression, with no new exemption or recursion source. Alternative rejected: staffer exclusion silently reduces the literal every-butler obligation. Module-disabled/failed states remain honest; declared does not falsely mean healthy.

[decision] Switchboard self-relay: in _wire_module_runtime, when the active self_healing module belongs to Switchboard and no external client is configured, supply a small call_tool adapter using async with FastMCP Client(self.mcp) per call. It calls the existing registered list_butlers and route tools over MCP, after registration, using the same result normalization and deadline. Other modules/daemons keep their existing clients. Alternative rejected: direct QA handler/database invocation crosses the MCP boundary; changing global connect_switchboard order or adding a long-lived self connection before server startup introduces avoidable lifecycle coupling. Real in-process MCP registration/route acceptance and closure controls must execute before claiming this path works.

[decision] Relay-only tools/lifecycle: retain report_error and read-only get_healing_status; remove retry_healing registration/handler and its inventory entry, direct dispatch, fallback metric and report_error's legacy active-attempt short-circuit. on_startup stores config/pool only; on_shutdown performs no dispatch or shared cleanup. Keep wire_runtime's public spawner/repo_root signature for module compatibility, but do not retain/use a module-local spawner dispatch reference. Alternative rejected: a registered retry tool that can still redispatch makes universal declaration operationally unsafe; a misleading no-op tool adds an unsupported model surface. Shared core.healing functions and existing QA calls remain untouched.

[decision] Legacy retry compatibility: do not rewrite src/butlers/api/routers/healing.py behavior. Terminal retry still creates its historical row; nonterminal/active fingerprint remains 409; injected in-process dispatch still behaves as its existing extension. Its existing daemon search must report dispatched=false when real relay MCP servers lack retry_healing. Existing investigating-but-undispatched history is not a newly launched investigation. Correct only stale API explanatory text directing operators to enable the old dispatcher, if necessary for same-change truthful documentation; no new central retry tool, authority or background pickup promise. Preserve positive extension and negative actual module-registration witnesses. Alternative rejected: moving this endpoint onto QA's gated publisher/scheduler or inventing a queued dispatch workflow is foreign/new behavior.

[decision] Configuration compatibility: accept all six current SelfHealingConfig keys and defaults with extra fields forbidden. enabled controls relay admission; legacy severity/concurrency/cooldown/breaker/timeout knobs are inert compatibility inputs and cannot override central QA gates/configuration. Existing runtime module state still gates calls. Do not silently repurpose legacy values as QA policy or introduce deprecated [healing] config. A configured disabled module is distinguishable from an undeclared/failed one.

[decision] Non-blocking and truthful guidance: restore the archived accepted one-to-two-second contract by an overall two-second deadline, rather than claiming the current composed timeouts satisfy it. Skill examples use actual seven report_error parameters and only the two real tools; reception, investigation, PR merge and deployment are separate states. Preserve safe diagnostic reporting, read-only status caveats and QA ownership; remove source-butler healing-agent commit/UNFIXABLE/publication instructions from the relay skill, with genuine investigation guidance remaining in the existing QA-owned skills/shared core contracts.
