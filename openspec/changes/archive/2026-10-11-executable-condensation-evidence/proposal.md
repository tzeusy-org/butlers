# Executable condensation evidence

## Why

A matching test name, line coverage, a deleted source path, or a smaller test
count cannot establish that a protected behavior still has an enforcing test.
The run17 condensation program requires a current survivor account before any
deletion. This first packet installs the proof protocol and its producer and
consumer; it deletes no existing test and changes no required CI predicate.

## What Changes

- Add source-bound, strict evidence for exact collected case multiplicity,
  phase outcomes, branch contexts and targeted mutation kills.
- Run proof mutations only in a disposable owned checkout with a finite
  process envelope, a durable journal and exact source/mode restoration.
- Add one stdlib consumer that detects removed tests and lost assertions or
  parameter declarations, admits only complete current evidence, and refuses
  unsupported catalog or attestation claims.
- Document truthful proof, UNKNOWN, survivor and administrative boundaries in
  the same change. Required guard activation waits for genuine native
  preparation qualification and ROOT's explicit release.

## Impact

Affected capability: testing, additive REQ-testing-053. Existing requirements,
REQ-testing-052, all CI event/fan-in predicates, coverage defaults, marker
selection, eleven computed children and budgets remain binding. The first
three real condensation clusters, shared-app isolation, catalog evidence and
all timing/delivery outcomes remain separate mandatory unfinished work.
