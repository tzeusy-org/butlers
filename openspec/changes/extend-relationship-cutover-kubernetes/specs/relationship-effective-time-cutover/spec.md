The future collector SHALL bind exact Kubernetes cluster trust identity, namespace UID, release identity/revision, authorized ordered chart/values/override input projection, admission installation, full target Git/tree/roster identities, immutable OCI digests and verified actual source/mutator bodies. Missing or partitioned-node termination, residual Jobs, unknown autoscalers/reconcilers, failed watch/permission or externally unfenced reconnect capability SHALL retain the fence and refuse. Only authorized infrastructural codes/counts/digests/identities/times may leave the collector, never row/fact/entity/contact data, SQL, raw command/environment/log text, credentials or key material.

UNKNOWN, FAILED, missing nodes, mismatched source or residue SHALL refuse. #### Scenario: Proposal does not adopt or activate the topology

- **WHEN** this source proposal is reviewed, validated or merged
- **THEN** no Kubernetes proof/custody choice, implementation, provisioning or live act is authorized by that event
- **AND** all eight old requirements and every old scenario remain binding and unchanged

#### Scenario: Complete credentialed actor discovery refuses omissions

- **WHEN** a foreign-labeled Pod, active/manual Job, credentialed init or ephemeral container, other-namespace or host client is planted alongside the expected fleet
- **THEN** the actual collector must include and exclude it or refuse before proof and DDL
- **AND** an empty label-filtered result, missing list/watch permission or opaque credential indirection cannot produce success

#### Scenario: Code and rendered target identity are independently verified

- **WHEN** a mutable tag, short projected GIT_SHA, changed roster/code mount, runtime dependency rewrite, init image or controller/credential-reference revision differs from the bound target
- **THEN** preparation or release refuses and retains the fence
- **AND** the unchanged complete target is a verified positive companion

#### Scenario: Controller recreation cannot revive an old client

- **WHEN** rollout restart, Helm rollback, liveness replacement, scale, CronJob schedule/manual Job or an ad-hoc start attempts to cross a held generation
- **THEN** admission refuses before creation or target DB connection, including the migration initContainer
- **AND** a partitioned or unconfirmed terminated process cannot be counted absent

#### Scenario: Competing invokers cannot reuse or clear the fence

- **WHEN** two actual invocations contend, a coordinator crashes or a receipt expires
- **THEN** the loser refuses and the durable fence/generation remains held until independently verified recovery
- **AND** no replayed authority, Lease expiry or automatic cleanup may start the old cohort

#### Scenario: Trust alternatives remain concrete and unselected

- **WHEN** an implementation proposes host-root, dedicated control-plane or external collector custody
- **THEN** its actual process/RBAC/key/rotation/restart/transport/isolation boundary needs exact changed-contract adoption before use
- **AND** the runtime-probe signer, general Secret mount or operator-provided evidence cannot substitute

#### Scenario: Forged stale mixed or cross-topology proof is refused

- **WHEN** signature, key window, purpose, schema/duplicate member, time, source/image/roster, cluster/namespace/release, actor set, database or fence binding is wrong
- **THEN** the actual parser and G refuse before DDL with unchanged data/index/stamp
- **AND** a valid same-epoch proof must reach the real registered admission

#### Scenario: Receipt and refusal outputs cannot block or clobber

- **WHEN** a receipt or error-output path is a FIFO, symlink, nonregular object or a foreign replaced target
- **THEN** bounded actual reads/writes refuse without hanging or overwriting the planted target

- **WHEN** the collector launches its fixed conformance tests with planted reachable DB/socket/API/key/output/other-invocation sentinels
- **THEN** every protected access is denied in that same runtime and teardown removes its full descendant domain
- **AND** incomplete population, residue, missing offline dependencies or an available host-daemon fallback refuses preparation

#### Scenario: No snapshot substitutes for pre-DDL exclusion

- **WHEN** a real second client holds the fact lock or is connected before G, or races a write after the session check
- **THEN** NOWAIT/session proof refuses the earlier conflict before DDL and the later write cannot run before transaction commit
- **AND** separate-connection readback verifies unchanged denied data/index/stamp and the held lifecycle fence

- **WHEN** release would recreate an old ReplicaSet, wrong image/source/roster/init actor, extra credentialed Pod or different desired schedule
- **THEN** it refuses with the fence held
- **AND** all required exact-target actors must start after commit and verify before normal admission resumes
