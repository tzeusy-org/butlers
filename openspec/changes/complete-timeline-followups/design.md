## Decisions and evidence

[Observed] The fleet route supports `before`, `limit`, repeated `butler`/`event_type`, and `trace`; it has no interval or histogram endpoint. Session event time is `started_at`, notification time `created_at`. Failed notifications join the Errors lens without becoming session events. `timeline_v1.py` owns source queries and filters. Preserve that projection and its content-blind session summary helper.

[Observed] TimelinePage has `r` refresh and conditional `n` latest via `usePageActions`. Shell spec owns `/` and Cmd/Ctrl+K. Use the same palette for search rather than introducing a local search surface. [Decision] This satisfies the original search-focus need through existing global search; Escape restores the invoking element under the shell's modal contract.

[Decision] Recent failures are bounded current-status observations, not unresolved work. A session has no triage/resolution flag, and the attention ledger is the wrong data source. Do not invent resolution or imply that an old failed attempt remains an undelivered logical notification after an independently successful retry. Copy is `Recent records marked failed (created in last 24h)` with `Runs` and `Delivery records` category counts. Opening an item is inspection, not acknowledgement.

## Density and interval contract

Add `GET /api/timeline/histogram?since=<RFC3339>&until=<RFC3339>` with existing repeated `butler`/`event_type` and `trace` filters. Both timestamps required, timezone-aware, aligned to whole UTC minutes; `since < until`; maximum 24 hours. Invalid or one-sided interval returns 422. Return `{data:[{start,end,count}],meta:{since,until,bucket_seconds:60,availability:"complete|partial|unavailable",expected_sources:0,healthy_sources:0,degraded_sources:[],degraded_butlers:[]}}`. UTC strings are normalized; exactly one ascending bucket per minute, zero-filled only for queried healthy sources. Counts are nonnegative integers over events, before visual heartbeat/maintenance collapsing. When any source fails, successful-source counts remain but the result is explicitly partial; never label it complete or all-clear. When all selected sources fail, show unavailable rather than a zero histogram. No event content, recipients, prompts or payloads enter aggregate DTOs.

Add optional paired `since`/`until` parameters to `GET /api/timeline`, with the same interval validation; absence preserves its existing unbounded cursor behavior. Queries enforce `[since, until)` plus the existing composite before cursor, type/butler/trace filters in SQL. Count and list share predicates/source eligibility, including the Errors lens's failed notifications, without fetching all events into Python. Add optional arguments to timeline_v1 rather than breaking its DTO schema. Reuse its fan-out degradation boundary; notification data remains queried once. Different source transactions need not form a global snapshot: each refresh is a current read and the UI must not promise transactional count/list equality during concurrent writes. Stable fixtures must agree exactly.

The UI defaults histogram to the last complete UTC hour (60 buckets). Provide Previous hour, Next hour (disabled beyond the current complete-hour boundary), and Latest hour controls. Explicit `since`/`until` URL keys own the chosen chart window; absent keys mean latest complete hour. Refresh recomputes only an implicit live window. A bucket selection atomically materializes the currently resolved chart since/until bounds (even when previously implicit) and writes paired `bucket_since`/`bucket_until` URL keys (one minute within the chart window); the list alone requests that minute using API `since`/`until`, resetting pagination and pinning to the selected interval. This loads history even when no selected event was previously loaded. The chart remains the surrounding hour. Clear selection removes bucket keys and restores live stream behavior; `n` latest also clears interval and bucket keys. Changing hour clears bucket selection; changing butler/type/trace retains valid interval bounds and resets list pagination. Existing `view`, `event`, `internal` semantics remain; selecting a bucket clears an event drawer target outside the new scope. Saved-view persistence continues to store existing filter fields only.

Malformed URL pairs or out-of-window bucket keys render an inline invalid-interval message and a Clear interval action; issue no silently broadened interval query. A valid bucket must be minute-aligned, exactly 60 seconds and contained in the chart interval. Back/forward/reload restores both intervals. Counts include machine events hidden by owner-mode collapsing; label the chart `All matching events` so raw count is not confused with visible rows. `internal` stays a presentation-only control and is not a count predicate.

Cache keys contain normalized UTC bounds plus existing type/butler/trace parameters; rapid transitions must not commit a previous query's result into the current selection. Existing poll-bus invalidation and degraded-source UI conventions apply. Do not retune unrelated polling or prefetch. Empty buckets remain selectable with an honest empty list. Use a single-tab-stop bar group with arrow-key selection and Enter/Space activation, accessible minute/count text, a textual summary, and Dispatch quantitative chart tokens; 60 separate tab stops are unnecessary. Reduced motion must not animate scroll.

## Recent-failure strip

Add `GET /api/timeline/attention?butler=...&trace=...`, intentionally independent of chart/type filters and selected historical interval. Server captures `until=now` once and `since=until-24h`; no caller-selectable time range. Return `{data:[{id,kind,butler,timestamp}],meta:{since,until,failed_sessions,failed_notifications,total,has_more,availability,expected_sources,healthy_sources,degraded_sources,degraded_butlers}}`, newest first, maximum 5 rows, stable tiebreak `(timestamp,kind,id)`. `kind` is `session` or `notification`. Counts are exact over healthy selected sources and `total` equals their sum; row limit never caps counts. Reuse canonical failure SQL and source boundary from timeline_v1. No summaries, recipient, prompt, error text or arbitrary target URLs in this new projection.

Session rows link to `/sessions/{id}`; notification rows link to `/timeline?event={id}` carrying butler/trace filters but clearing histogram/bucket bounds. The existing off-page event resolver opens the event independently of list pagination. The strip is always explicitly labelled last 24h, even when chart selection is historical. It displays at most 5 rows and `Showing 5 of N` when truncated. Collapse is component-local, defaults expanded, resets on remount, uses `aria-expanded`/`aria-controls`, and retains counts and degradation indicator. No navigation badge or new persistent preference. Healthy zero results say `No matching records currently marked failed`; partial/unavailable sources never say all-clear. A prior result may remain visibly stale during refresh failure with Retry. Query refresh follows the existing timeline poll-bus convention. Repeated reads have no mutations; concurrent retry updates become visible on subsequent refresh without an invented resolution claim.

## Keyboard flow

Register j/k through useListTriage/useRegisterShortcut (with a thin real-DOM-focus adapter following the existing Sessions/Issues pattern) and use real focus on rendered primary disclosure controls in current visual order. First j enters first row; first k enters last; ends clamp, never wrap or fetch extra pages implicitly. Collapsed heartbeat/maintenance groups count as one rendered row; expanded nested evidence that lacks a disclosure control is not an invented selectable row. Enter remains the focused control's native activation, avoiding a second global handler/double-toggle. The event drawer retains its own modal choreography and Escape close/focus return.

Preserve focused event/group identity across in-place refetch; if removed, focus the nearest surviving row by prior index without resetting to row zero. Live arrivals while history is pinned preserve both snapshot and focus. Suppress page shortcuts in editable fields, contentEditable, composing IME, dialogs and handled modifier combinations under the existing shortcut registry. Add palette-only commands with useRegisterCommands for existing All, Errors only and Notifications presets; invoke the current selectBuiltInView path. Existing r/n and global /, Cmd/Ctrl+K retain behavior. Keyboard hints/help derive from the shortcut registrations; palette-only presets carry no invented shortcut or help-sheet binding.

## Rollout, review and rollback

Three vertical children share TimelinePage and therefore run serially: density+seek, attention, keyboard. Each can revert independently; attention shares only the stable additive source filter helper from density. No migration or destructive operation. A frontend rollback leaves harmless additive API readers; backend rollback requires first removing interval consumers or retaining the additive routes until clients refresh. Never claim mixed-version interval enforcement when an old server ignores added query fields: release backend before frontend and validate the endpoint during integration. Children remain blocked until the exact artifact is approved. Parent reconciliation runs after all children, verifies combined route/focus/degraded behavior, then archives the approved change without overwriting active deltas.

If the owner approves density and keyboard but not the attention option, sequence keyboard directly after density, retain attention as blocked, and scope reconciliation to delivered approval without closing the original unresolved objective. Serialization is an ownership rule, not a dependency requiring an unapproved product decision.

## Explicit aggregate source availability

Both new aggregate endpoints return `expected_sources` and `healthy_sources` as nonnegative integer counts plus `availability: complete|partial|unavailable`. A source unit is one selected session butler pool, or the single notifications pool when notifications are selected. Histogram source/type eligibility is exactly the existing timeline rule: session/error selects session units; notification or error selects the notifications unit, applying only-failed when selected only through error. Attention always selects both failure source families. Session target names are the unique explicit butler names when supplied, otherwise `DatabaseManager.butler_names`; a requested unavailable/unknown name is an expected failed unit, not silently omitted. Notification butler filtering never multiplies its single source unit. Capture the target set once per request before querying.

A successful query, including zero rows, makes its unit healthy. Query failure, missing table, or missing selected pool makes the expected unit unhealthy. In particular an absent Switchboard pool is an unavailable notifications unit for these new aggregates, even though the legacy list historically skips its KeyError. Do not change that old list compatibility behavior in this work; the histogram explicitly discloses the selected source it could not count. Compute complete when healthy==expected (including the vacuous expected==0 case for a filter selecting no recognized source); partial when 0<healthy<expected; unavailable when expected>0 and healthy==0. No inference from an empty results map or degraded family-name count. Zero expected sources is labelled No matching event sources, not fleet all-clear. `degraded_butlers` identifies failed session units and `degraded_sources` contains each affected family once. Returned buckets/counts sum only successful units, remain lower-bound observations when partial, and do not render as measurements when unavailable.

Required matrix: notification-only with missing Switchboard -> expected 1, healthy 0, unavailable; sessions-only one of two pools down -> 2/1 partial; sessions-only both down -> 2/0 unavailable; all selected units healthy with zero events -> complete zeros; no recognized selected family -> 0/0 complete with No matching event sources. Attention's combined source matrix follows the same arithmetic. Test missing configuration independently from query failure and partial fan-out, in API tests as well as UI availability rendering.

## Mutable failure status is not historical occurrence evidence

`POST /api/notifications/ack-failed` changes notification status from failed to read, and retry claiming also changes failed to read before the new delivery succeeds (`routers/notifications.py`, acknowledgement and retry handlers). Consequently this strip counts only records CREATED within its captured 24h window and CURRENTLY marked failed at query time. It is neither an immutable failed-attempt count nor a verified unresolved-condition count. Labels are Recent records marked failed (created in last 24h), Runs, and Delivery records; healthy empty copy is No matching records currently marked failed. Do not say failures occurred, delivery recovered, or all historical attempts succeeded. Acknowledgement and retry claim remove a delivery record on the next read without proving recovery. The strip itself performs neither action. Tests exercise each status transition before successful delivery as well as ordinary success and pending exclusion. Source authority remains existing mutable records, not a new event ledger.

When selecting a bucket from the implicit latest-hour view, persist the resolved chart since/until and bucket_since/bucket_until together in one URL update. A subsequent hour rollover/reload must retain that explicit historical scope rather than resolving a new chart hour and declaring the chosen minute invalid.
