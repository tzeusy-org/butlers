# Project shape and vision audit

**Date:** 2026-09-23

**Review base:** `5802fcba23ea8fcd47741f5dbe9045aef6cbafbb`

**Scope:** all five project-shape pillars, with vertical checks from doctrine through RFC, OpenSpec, topology, representative code/tests, operating evidence, and Beads.
**Authority boundary:** research and backlog planning. No doctrine or draft-spec adoption, live replay, credential change, deployment, or historical delivery was authorized by this audit.

## Verdict

**The project's shape is complete as a navigation structure but is not yet a reliable statement of product readiness.** All five pillars and their doctrine navigators exist. On the committed review base, the shape scanner returned `SHAPE_LEVEL=SHAPED`, `MATURE_TRACEABILITY_GATE=FAIL`, 18/35 RFCs with explicit doctrine references, and 103/388 active spec files with `Source:` lines; all 388 have scenarios. The active corpus there comprises 194 canonical files (29 sourced) and 194 active-change files (74 sourced). A separate scan of the dirty audit root returned 117/400: two untracked recovery drafts added 12 sourced files, and dirty edits added `Source:` lines to two existing active specs. These are conservative text heuristics, so they identify a source-lineage problem but do not by themselves prove that the unsourced requirements are wrong.

The more consequential drift is behavioral: a dated, content-blind live review records the fleet appearing healthy while routes and QA schedules were disabled. A second code path labels a failed ingress event `ingested` without actually replaying its target delivery. These violate the reliability and trustworthy-autonomy purpose that [Vision](../../about/heart-and-soul/vision.md) puts above feature count. Both have separate draft OpenSpec changes in the active workspace; neither draft is adoption or implementation authority.

## The load-bearing mandate

The standard for this audit comes from [Vision](../../about/heart-and-soul/vision.md): one owner controls data and credentials (lines 5-13, 60-63); domain butlers own life domains while staffers support infrastructure (15-29); inter-butler work is Switchboard-mediated (71-78); the daemon is deterministic and LLM judgment lives in ephemeral sessions (80-84); and success means weeks of unattended operation, correct routing, useful unsolicited insight, and less mental labor for the owner (120-137). [v1](../../about/heart-and-soul/v1.md) makes those aims testable: >90% routing accuracy, reliable schedules, seven uninterrupted days, daily use across three domains, and adaptive proactive delivery (208-233).

The audit treats an RFC or spec as authoritative only to the extent it is adopted in the current hierarchy. An unarchived change, a code stub, a successful unit test, and an operator-facing green badge each prove different things.
