# Scoped planner evidence and remaining obligations

The planner is feedback tooling. It does not establish merge readiness or run
pytest. `make test-plan BASE=<immutable-base>` includes committed, staged,
unstaged and untracked changes. `--json` emits `pr-test-plan.v1`; its `mode`,
`backend_applicable`, reason codes and qualified cost are authoritative.
`scope` and candidate paths from the Python library are ownership hints only.
Unknown ownership, stale readers, missing targets, shared boundaries and absent
compatible costs produce FULL. The legacy runner refuses FULL execution.

## Reader and target authority

`python3 scripts/build_test_resource_map.py --check` freshly hashes and scans
current tests, roster, scripts, source helpers and root conftest without
importing repository code. The checked registry binds each producer and reviewed
declaration. Finite paths are over-approximations. Unknown IO retains every
resource family; an unproved helper frontier retains every test and forces FULL.
A matching file/directory name is not proof of complete reader ownership.

Reviewed dynamic declarations bind all source witnesses. A no-reader markdown
exception binds the entire scanned source set and a reason; absent declarations
or an empty map cannot authorize docs skips. Adding a real OpenSpec reader
invalidates the old registry until its source-bound edge is regenerated and
reviewed. Frontend resources add backend readers and preserve frontend gates.
Executable deployment/configuration and unknown paths remain FULL.

Literal path-shaped data is recorded separately from direct file IO. A reviewed
literal-data declaration pins its exact source and cannot remove a direct read
or clear unresolved IO. The producer's own family vocabulary is such data; its
remaining unresolved IO still forces FULL. A helper may use a bounded consumer
declaration only with the complete current source-set digest, every observed
import consumer (including roster and ancestor conftests), and a reviewed caller
audit. Finite module names and file-loader paths use the same conservative
assignment/path resolver as reader discovery; every resolved value must name
current indexed source. An opaque dynamic loader or unindexed local import
refuses this refinement. Static imports supply a lower bound, not proof that an
unobserved consumer is absent; empty or stale consumer claims never authorize
NONE. Current helper frontiers remain unproved unless those independent
obligations are actually met.

A loader assigned to another name, passed as a value or held in a container
escapes finite direct-call analysis. That source remains opaque even with a
fresh source-set witness, so a declared list cannot omit its real consumers.

Every static test target must exist. Only an actual Git deletion may select its
surviving parent; an unrelated missing static target must not widen into a
single-runner full job. Root-wide parents, unsupported helpers, contacts backfill,
module wiring and multiple connector families remain FULL. Roster API changes
retain roster tests and conservative tests/api ownership pending exact importer
qualification. Two credential producers remain STATIC_OWNER_UNPROVED until the
complete historical behavior/current-consumer/executing-survivor join exists;
existing tests/config directory names alone do not authorize narrowing.

## Empirical cost has no guessed fallback

full/affected source, configuration, worker, tracer, CPU and artifact identities.
Whole-file serial setup/call/teardown costs plus the complete measured job time
outside their phase union account for setup, worker startup, all collections,
coordination, upload and finalization. Costs are never divided by workers.

with the same full overhead, labelled provisional. Otherwise missing costs stay
UNKNOWN and FULL. A profile value is an estimate, never measured PR elapsed time.

Production planning without compatible observed context remains FULL even if
an unadmitted candidate file exists. No wall-clock gain is claimed.
