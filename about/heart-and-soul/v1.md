# v1 Scope

This document is the scope boundary. If a capability is not named here, it
waits. Scope debates end here; descriptions and status do not live here.

## What v1 Is

One deployment running every agent in `roster/` as a persistent daemon, with
intelligence confined to ephemeral goal invocations: one lead per goal and
optional depth-1 children, launched and brokered by the Switchboard control
plane (see [architecture.md](architecture.md) and
[RFC 0038](../legends-and-lore/rfcs/0038-goal-runtime-and-capability-authorization.md)).
v1 ships on this goal runtime after its hard cutover (owner decision,
2026-10-14). v1 has three kinds of parts:

- **Staffers** (infrastructure specialists, never owners of a life domain and
  excluded from briefings): Switchboard (ingress and goal control plane), Messenger (outbound delivery),
  QA (error detection and investigation), Concierge (read-only system-plane
  answers, RFC 0030).
- **Domain butlers** (one life domain each, bound by a manifesto): General,
  Health, Relationship, Finance, Education, Travel, Home, Lifestyle, and
  Chronicler (retrospective reconstruction from other butlers' evidence; it
  does not plan, ingest, or notify beyond the daily day-close and its opted-in
  once-daily gap interview correction prompt, and distills
  only into a private schema it owns, RFC 0014).
- **Capabilities** that butlers compose: modules, connectors, the dashboard,
  the identity system, situational awareness (context bus, RFC 0009; proactive
  insight delivery, RFC 0011), and OpenTelemetry observability. The scope
  registry for those is the three name lists below; descriptions and status
  live in [lay-and-land/components.md](../lay-and-land/components.md) and in
  each capability's spec under `openspec/specs/`.

### Modules

Memory, Contacts, Calendar, Email, Telegram, Approvals, Pipeline,
Self-healing, Home Assistant, Google Drive, Google Health, WhatsApp, Steam,
Insight broker, Dashboard read (Concierge). Self-healing is the error relay
to the QA staffer (RFC 0015). Metrics and Document renderer were retired
from v1 by owner decision on 2026-10-04.

### Connectors

Telegram bot, Telegram user client, Gmail, Google Calendar, Google Drive,
Google Health, Home Assistant, OwnTracks, Spotify, Steam, ActivityWatch,
WhatsApp user client, Live listener, Heartbeat. This list is the fixed v1
connector set that RFC 0018 anchors to; a connector not named here is deferred, and the deferral
rationale lives in that RFC and the ideas ledger.

Context feeds (deterministic scheduled pulls owned by one butler, not
`ingest.v1` connectors): Atmosphere (Open-Meteo weather, air quality and
pollen, Home), Flight status (AviationStack status for booked legs, Travel),
SimpleFIN bank feed (balances and transactions, Finance). Admitted to v1 by
owner decision on 2026-10-08; a context feed not named here is deferred like
a connector. A GitHub activity feed stays deferred.

### Dashboard

The operator console, as the RFC 0038 D19 owner surface: goals with lineage,
effects, approvals and Stop; domain regions; contacts and identity; ingestion
monitoring; the settings console (health, model catalog, spend, owner-confirmed
data export and wipe); an append-only audit log; and signed outbound webhooks
with retry. Its role and boundaries are defined in
`docs/frontend/purpose-and-single-pane.md`.

## What v1 Defers

Explicitly out of scope. No v1 work is designed to "prepare for" these at the
cost of v1 simplicity.

- **Discord.** Deferred by owner decision on 2026-10-04; the draft connector
  is retired. A return goes through a new proposal (RFC 0018, ideas ledger).
- **Multi-user support.** One user, one deployment. No accounts, no tenants.
- **Mobile application.** The dashboard is web-only. No native iOS or Android
  client.
- **Voice as an interface.** No speech-to-text or text-to-speech at the butler
  level. Connector/dashboard ingress may transcribe the verified owner's own
  non-forwarded Telegram voice note, Telegram audio file or dashboard recording
  through instruction-free ASR before admitting text under RFC 0038 D5/D18
  (modality decision `bu-2utmy5`, 2026-10-20). Authorship comes from bound ingress
  evidence, not transcript words; forwarded, quoted, room and non-owner material
  stays third-party. Finite length and execution bounds remain engineering
  configuration. This does not authorize an outside speech service, household
  or room voice, duplex/realtime voice, deployment, or a butler-level speech
  capability. Existing live-listener transport is not an owner-audio exception;
  in-room voice egress remains a gated proposal. Spoken replies/TTS are a
  separate contract, not part of this audio-authorship amendment.
- **Managed setup.** The Helm chart and compose files are deployment
  artifacts, not an installer. No setup wizard, no one-click deploy.
- **Plugin marketplace.** No third-party module distribution or plugin API
  versioning.
- **Offline reasoning.** State persists locally; reasoning needs LLM access.
- **End-to-end encryption.** The owner owns the database; see
  [security.md](security.md).
- **Multi-LLM orchestration within one invocation.** Each lead or child
  invocation uses one provider; separate invocations of a goal may differ.

## Platform Targets

Linux (primary) and macOS (development); Python 3.12+; PostgreSQL 15+ with
JSONB; Docker Compose or k3s via the in-repo Helm chart; Claude Code as the
primary LLM runtime with model routing to Codex, Gemini CLI and OpenCode.

## Success Criteria

v1 is complete when:

1. Every staffer and domain butler in `roster/` runs concurrently in one
   deployment and handles its declared responsibilities.
2. Owner requests from every active ingress connector are admitted as goals,
   and on the replay evaluation set the goal runtime meets or beats the
   recorded outcomes of the classify-and-route runtime it replaced, graded on
   whole-goal success and owner corrections (lifestyle-only ambient connectors
   such as Steam are excluded from this set).
3. The adversarial authorization suite of RFC 0038 produces zero unauthorized
   effects.
4. Scheduled tasks fire on their cron cadence and retry transient failures.
5. The memory subsystem stores, retrieves, and consolidates facts across
   sessions.
6. The dashboard shows goals with their lineage, effects and approvals, each
   domain region's data and obligations, contacts, and ingestion flow in real
   time (RFC 0038 D19).
7. The system runs seven consecutive days with no manual intervention beyond
   LLM API key rotation.
8. The owner uses the system daily across at least three domains.
9. Proactive insights arrive at a sustainable cadence without manual tuning,
   and disengagement lowers the rank of ignored categories.

Evidence against these criteria lives in tests, benchmarks
(`tests/benchmarks/`), and Beads, never in this file; a dated status line here
goes stale the day it is written.

## Anti-Patterns

- Building v1 features with multi-user "hooks".
- Deferring reliability work because "it is just v1".
- Expanding connector coverage before existing connectors are solid.
- Adding modules no butler in the roster uses.
- Designing plugin abstractions before the internal module API is stable.
